# 06 · 提示工程

> 状态：🏗 重写中 ｜ 前置：04_llm_basics

## 这个模块解决什么问题

同一个模型，提示词差一句话，输出质量差一个档次。这个模块用「运营商流量包客服」这个案例，把提示词从一句话逐步优化成结构化指令，再补上思维链、自洽性和提示注入攻防。

## 知识点

- [x] 提示工程是什么、为什么有效（对齐、上下文学习）
- [x] 关键原则：指令明确、给出角色、给出示例、限定输出格式
- [x] 提示词的典型构成：角色 + 任务 + 约束 + 示例 + 输出格式
- [x] 少样本（Few-shot）与零样本（Zero-shot）的效果差异
- [x] 用提示词实现「结构化输出」（配合 JSON 约束）
- [x] 思维链（CoT）：让模型先推理再给结论
- [x] 自洽性（Self-Consistency）：多次采样投票，稳定性换成本
- [x] 提示注入攻击：直接注入、越权指令、角色劫持
- [x] 防御：输入隔离、指令优先级声明、输出校验

## 验收标准

1. 拿你自己的案例说：提示词从 v1 到 v5 分别改了什么、每次改完效果怎么衡量。
2. Few-shot 的示例该怎么选？示例写错了会怎样（模型会学坏）。
3. CoT 为什么有效？什么任务上反而会变差（简单任务 + 长链会引入噪声）。
4. 自洽性为什么能提升准确率？成本增加多少、什么时候不值得。（展开见下）
5. 提示注入和 SQL 注入的本质区别是什么？为什么「过滤关键字」防不住。
6. 生产环境下你怎么在架构层面防注入（权限最小化、工具白名单、输出审核）。
