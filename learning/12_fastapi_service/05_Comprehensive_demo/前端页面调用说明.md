# 电商商品管理系统 · 前端主要交互与接口对照

## 一、全局约定

- API 基础路径：`const API_BASE = "/api"`
- 所有请求经 `api(url, options)` 统一封装
- 分页默认：`page=1`、`page_size=5`

---

## 二、查（列表 / 搜索 / 分页）

| 触发 | 函数 | 方法 | URL |
|---|---|---|---|
| 页面初始化、搜索、重置、翻页 | `loadProducts()` | `GET` | `/api/products` |
| 点「搜索」 | `searchProducts()` → `loadProducts()` | `GET` | `/api/products` |
| 点「重置」 | `resetSearch()` → `loadProducts()` | `GET` | `/api/products` |
| 点页码/上一页/下一页 | `goPage(p)` → `loadProducts()` | `GET` | `/api/products` |

> 分页区由 `renderPagination()` 生成，点击走 `goPage(p)`。

## 八、按 ID 查询 / 查看详情（只读窗体，2026-11-27 新增）

| 触发 | 函数 | 方法 | URL |
|---|---|---|---|
| 工具栏输入 ID → 点「按ID查询」或按回车 | `queryById()` → `openViewModal(id)` | `GET` | `/api/products/{id}` |
| 点表格里的商品名 | `openViewModal(id)` | `GET` | `/api/products/{id}` |
| 点行内「查看」按钮 | `openViewModal(id)` | `GET` | `/api/products/{id}` |

- 三条入口共用同一个 `openViewModal(id)`，都只调 `get_product` 这一条现有接口，**后端零改动**。
- 查无此 ID 时后端返回 `404 {"detail": "商品X不存在"}`，由 `api()` 转成 toast 提示。
- 窗体为只读，展示 `id / name / category / price / stock / created_at`；回显用 `textContent` 写入，不把用户输入当 HTML 解析。
- 「编辑此商品」先 `closeViewModal()`，再走 `openEditModal(id)`（见第三节）。
- 相关纯前端无请求函数：`closeViewModal()`、`editFromView()`、`fmtTime()`。

| 操作 | 方法 | URL | 编写顺序 |
|---|---|---|---|
| 查全部/搜索/分页 | `GET` | `/api/products` | 2 |
| 查单个 | `GET` | `/api/products/{id}` | 3 |
| 按ID查询 / 查看详情 | `GET` | `/api/products/{id}` | 复用 3 |
| 增 | `POST` | `/api/products` | 4 |
| 改 | `PUT` | `/api/products/{id}` | 6 |
| 删 | `DELETE` | `/api/products/{id}` | 5 |

> 其余纯前端无请求的函数：`openCreateModal()`、`closeModal()`、`clearErrors()`、`showToast()`、`renderTable()`、`renderPagination()`。
