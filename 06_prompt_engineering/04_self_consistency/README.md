# 自洽性（Self-Consistency）｜面试问答卡

> 代码：[`self_consistency.py`](./self_consistency.py) ｜ 模块说明：[`../README.md`](../README.md)

这份笔记按「被问到时怎么答」组织，不罗列知识点。定位：**面试高频、生产低频**——值钱的是「LLM 输出可靠性 / 置信度 / 评测」这条判断线，不是那十几行投票代码。

## Q1 它解决什么问题？为什么能提升准确率？

难题往往有多条不同推理路径通向同一个正确答案，而错误答案分散在各自的错路径上。贪心解码（`temperature=0`）只走一条，走错就错了。做法是 CoT 提示 + `temperature 0.7~1.0` 采样 N 条**不同的推理链**，只抽每条的最终答案做多数投票，相当于把「走了哪条路径」这个隐变量平均掉（边缘化）。

> 出处：Wang et al., *Self-Consistency Improves Chain of Thought Reasoning in Language Models*（ICLR 2023）。公开基准上比单次 CoT 高 5~15%，但那是 GSM8K / MATH 的结果，**不能当自己项目的数字**。

**追问 · 为什么不能用 `temperature=0`？** 5 次输出几乎相同，投票退化成「同一个答案投 5 票」，一致率恒为 1.0，测不出稳定性。自洽性靠的是先允许分歧、再看分歧收不收敛。

**追问 · 四个生效前提？** ① 同一个问题多次采样 ② 必须有 CoT（没有推理过程就只是同一判断在抖）③ 答案空间离散（判断 / 数学 / 选择，开放式生成无法投票）④ `temperature > 0`。缺任何一条，投票都没意义。

## Q2 成本增加多少？怎么压回来？

不背数字，从 `resp.usage` 和 `time.perf_counter()` 实测。定性关系：

| 维度 | 关系 | 原因 |
|---|---|---|
| completion tokens | ≈ N× | 每次都要重新生成 |
| prompt tokens | ≈ 1× 量级 | 相同前缀命中缓存后几乎不计费 |
| 延迟（串行） | ≈ N× | 请求一个接一个 |
| 延迟（并行） | ≈ 1× + 抖动 | 同时发出、一起等 |

所以**成本增量集中在输出 token，整体不是 N 倍**；延迟只有改成并行调用才压得回来。生产里还要配缓存、超时降级。

**追问 · N 取多少？** 边际收益递减，K=5 已拿到大部分收益，K=20 之后提升很小而成本线性增长。实际按「单次错误的代价」定，不按固定值。

## Q3 什么时候不该用？

**明确不用**：聊天、RAG 问答、创意生成、低风险批量分类；推理模型（o1 / R1 类）内部已做多路径推理，通用场景不再手写。

**选择性使用**：高风险 + 离散答案 + 单次错误代价大的节点——金融计算、法务合规判断、根因分析、风险评估、内容审核。

**追问 · 2026 年还需要手写吗？** 生产里更常见的落地形态不是「取多数答案」，而是把**一致率当置信度**：低一致率转人工（HITL）、按难度**路由**（简单问题单次、复杂问题才多采样）、评测阶段多次采样降方差。小模型上多采样甚至可能把原本正确的贪心答案翻错。

## Q4 工程上最容易踩的坑

- **解析层**：模型返回是字符串，可能带 ```json 包裹、LaTeX 公式、解释文字。正则只找 `{...}` 时，公式里的 `\frac{2}{5}` 会被当成 JSON 块，`json.loads` 直接抛 `JSONDecodeError`。要收紧匹配并对解析失败兜底。
- **废票**：`Counter` 不校验内容，`None` 也是合法 key；不过滤会凑出假的 1.0 一致率。
- **输出校验**：禁止用 `eval`（模型输出是不可信输入）、禁止 `'true' in text` 字符串判断（「不准确」会误判）。
- **可移植性**：脚本在二级子目录，从仓库根运行必须自己锚定 `sys.path`，否则报 `ModuleNotFoundError`。正解是 `pyproject.toml` + `pip install -e .`。
